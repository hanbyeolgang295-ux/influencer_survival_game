# [프로젝트 결과 보고서] 객체 지향 기반 캔슬 컬처 기반 게임
**프로젝트명:** 100만 유튜버, 나락을 피해라!
**팀명/조:** 객체 지향 프로그래밍 팀 프로젝트 7조

---

## 1. 프로젝트 개요 및 기획 의도
현대 소셜 미디어 생태계에서 발생하는 맹목적 환호와 가혹한 '캔슬 컬처(Cancel Culture)' 현상을 객체 지향 프로그래밍(OOP)을 통해 시스템적으로 모델링한 텍스트 기반 생존 시뮬레이션입니다.

본 프로젝트는 100만 구독자를 보유한 가상의 인플루언서를 주체(Object)로 설정하여, 단순한 수치 성장을 넘어선 '사회적 딜레마'와 '지속 가능한 생존'에 대한 사회과학적 질문을 데이터와 알고리즘으로 풀어내는 것을 목표로 합니다. 대중의 광기와 심판 속에서 명분과 실리를 모두 지켜내야 하는 현대 인플루언서 생태계의 취약성을 구조적으로 체감할 수 있도록 기획되었습니다.

## 2. 시뮬레이션 핵심 메커니즘 (Key Mechanisms)
본 시스템은 플레이어의 몰입을 극대화하고 현실적인 시뮬레이션을 구현하기 위해 다음 3가지 핵심 룰을 기반으로 구동됩니다.

* **제로섬(Zero-Sum) 딜레마 기반 의사결정**
    단순한 '선악' 구조를 탈피하고 철저한 트레이드오프(Trade-off)를 구현했습니다. 평판을 방어하기 위한 자숙 선택이 수익 하락을 초래하고, 정면 돌파를 선택하면 인지도가 오르나 안티팬이 급증하는 등 모든 의사결정이 가혹한 기회비용을 요구하도록 모델링되었습니다.
* **데이터 상태(Flag) 추적을 통한 인과율(업보) 시스템**
    플레이어가 단기적 위기를 모면하기 위해 내린 비도덕적 타협이나 거짓말은 시스템 내부에 상태 값(Flag)으로 은밀히 기록됩니다. 이 데이터는 일정 시간(Time Flow)이 흐른 뒤 파멸적인 강제 사건(예: 국세청 세무조사)으로 발동하여, 선택의 나비효과를 알고리즘으로 구현했습니다.
* **7대 사회적 자본(Social Capital) 매개변수 통제**
    인플루언서의 생존 기반을 7가지 스탯(멘탈, 평판, 충성팬, 안티팬, 인지도, 인맥, 수익)으로 수치화했습니다. 하나의 지표라도 임계치에 도달할 경우(예: 멘탈 0 이하, 안티팬 100 이상) 시스템이 즉각적인 조기 종료(Early Game Over)를 선언하도록 설계되었습니다.

## 3. 시스템 아키텍처 및 OOP 설계 (System Architecture)
데이터와 비즈니스 로직을 완벽히 분리한 데이터 주도 설계(Data-Driven Architecture)를 채택하여 시스템의 확장성과 유지보수성을 극대화했습니다.

### 3.1. 핵심 클래스 구조
* **ScenarioGame:** 7일간의 루프, 무작위 사건 배열, 상태 플래그(flags) 및 완료 상태를 총괄 관장하는 메인 게임 엔진입니다.
* **Character & Stats:** 시뮬레이션의 주체인 캐릭터와 7대 사회적 자본을 객체화했습니다. 특히 스탯의 유효 범위를 벗어난 데이터 오염을 막기 위해 _clamp() 메서드를 통한 캡슐화(Encapsulation)를 적용했습니다.
* **Event & Choice:** 사건과 의사결정을 정의하는 모델입니다. 플레이어의 선택은 즉각적인 스탯 변화(effects)와 미래 상태 변수(set_flags)를 동시에 제어합니다.

### 3.2. 객체 지향 문법의 유의미한 적용
* **다형성(Polymorphism)과 상속:** Event 부모 클래스를 상속받는 DecisionEvent(선택형)와 ForcedEvent(강제형)는 엔진으로부터 동일한 resolve() 인터페이스를 호출받지만, 내부적으로는 사용자 입력을 대기하거나 강제 연산을 수행하는 등 상상이 동작합니다.
* **매직 메소드(Magic Methods) 활용:** 객체 지향의 편의성을 극대화하기 위해 __str__(상태 및 결과 출력), __len__(스탯/선택지 개수 반환), __iter__(순회), __getitem__(인덱싱 접근) 등을 시스템 내부에 적극적으로 적용했습니다.
* **사용자 정의 예외 처리(Custom Exceptions):** 런타임 환경의 안정성을 위해 에러 클래스를 상속 구조로 직접 설계했습니다. InvalidChoiceError(잘못된 번호 입력), UnknownStatError(없는 스탯 조작), ScenarioLoadError(데이터 손상) 등을 구축하여 예기치 못한 에러 발생 시에도 프로그램이 다운되지 않는 견고한 방어 로직을 완성했습니다.
